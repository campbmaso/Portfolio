## The operator’s task

A measurement is useful only if the operator can capture it, evaluate its validity in real time, and easily drill down later. At Sensors, I led product requirements, UX design, and rollout planning for a rearchitected software platform across the methane measurement portfolio.

The work started with our continuous monitoring product with web-accessible software and later rolled out to edge software to support our Bar Hole Sampler and HI-FLOW 2 products. I worked with the engineering team to build a more intuitive user experience with click-optimized navigation, progressive disclosure, and accessibility + preference controls.

## Decision 1: automate capture and preserve context

No amount of elegant in-app interactive dashboards can overcome missing data. So in the redesign, we started recording data the second the user starts sampling with no additional user actions required. We also automatically end and save the test as a “session” when the user powers the device down, making it so the user never misses any data from a field session. We simplified data annotations for the user, and made them easy to view in the analytics page.

This simplified the live measurement process, and made our data collection a more robust foundation for the rest of the redesign.

## Decision 2: keep device controls accessible

Switching device mode is a primary action during measurement. I made accessibility of those controls an explicit UX requirement. The interface needed to support what operators do while collecting data, alongside the later task of inspecting results.

## Decision 3: in-app data visualization and analytics

In the redesign, we wanted to support users throughout their data collection and reporting journey from beginning to end. To do this, we built out interactive visualization within the application with custom views catered towards their measurement. For example, along with a line chart of plotted measurement data, we provided a connected timeline view to enable users to easily see which measurement mode they were in during that portion of the test along with their annotation entries. This set of visualizations showed only the core information to the user, while allowing them to scrub through the data for a more detailed look, select specific time ranges, or even play back the test at different speeds. If the user wanted more from the data, we still offered csv or even full db exports for more advanced analytics.

## Launch and limits

The software redesign has launched. My responsibility covered requirements ownership, UX design, and rollout planning, alongside engineering and commercial collaborators.
